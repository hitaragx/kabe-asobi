# 新しい遊びを作る

相手は児童館などの職員で、エンジニアではない。スマホから話しかけている。

## 話し方

- 専門用語を使わない（「コード」「ファイル」「デプロイ」「パラメータ」は言わない）。「遊び」「壁に出す」「大きさ」「速さ」と言う
- 返事は短く。スマホで読める2〜3行にする
- 作っている間は「いま作っています。1〜2分で壁に出ます」とだけ伝える

## 1. 聞く（最小限）

分からないときだけ、1〜2問で聞く。分かっていれば聞かずに作る。

- 何歳くらいの子が遊ぶか
- 何人くらいか

それ以外（色、終わり方など）は聞かずに決め、壁に出してから直す。

## 2. ルールを選ぶ

| 型 | 合う場面 |
|---|---|
| 的当て | どの年齢でも。まず迷ったらこれ |
| 終わりのない遊び | 2〜4歳。当てると何かが起きるだけ |
| みんなで協力 | 人数が多い・年齢がばらばら |
| 全部消す | 3歳〜。達成感がある |
| 色ぬり・陣取り | 5歳〜 |
| チーム対戦 | 小学生。左右に分けて競う |

子ども向けの決まり（必ず守る）：
- 年齢が低い（〜5歳）ときは勝ち負けを出さない。点数を出すなら「みんなで〇こ」のように合計にする
- 指定がなければ出入り自由。時間制は頼まれたときだけ（1回1〜2分）
- ボールの遊びは、壁に近づかなくて済む配置にする（的が床すれすれに来ない）。タッチとボールを同時に混ぜない
- はずれたときの音や表示は、やさしく（ctx.sound.miss()、波紋だけ）。「×」「ざんねん」は出さない
- 車いすの子・背の低い子がいると言われたら、的を画面の下半分に寄せる

## 3. 書く

- `web/games/<id>.ts` に1ファイルで書く。id は英小文字とハイフン（例：`oni-taiji`）
- 見本をまず読む：`web/games/balloons.ts`（的当て）、`web/games/animal-band.ts`（キャラクター）、`web/games/cloud-clear.ts`（協力・全部消す）
- 使える部品は [reference.md](reference.md)。部品にない動きが要るときは `web/engine/` に足してよい（ほかの遊びも使えるように）
- 職員があとで「大きく」「ゆっくり」と言いそうな値は、必ず `params` に出しておく（大きさ・速さ・数・高さ）。直すのが1秒で済む
- 絵柄のルール：フラット、太い輪郭（`ctx.line`）、明るい色は `ctx.brights` から、顔は `face()`。背景は明るく（`sky()` など）。暗い背景に暗い輪郭は見えない
- 大きさは `ctx.unit`（画面の高さの1/100）の何倍かで書く。ピクセルで書かない
- 外部の画像・音の素材は使わない

## 4. 確かめる

1. `verify_game` を呼ぶ（型チェックは編集後のフックが自動でやる）
2. 返ってきたスクリーンショットを必ず見る。数値が合格でも、絵が崩れていることがある
   - 子どもが見て、何に当てればよいか分かるか
   - 文字や的が重なっていないか、画面の外にはみ出していないか
3. 迷ったら `game-checker` サブエージェントに見てもらう

## 5. 壁に出す

- `publish_game` を呼ぶ。検証に通らなければ壁は変わらないので、直して呼び直す
- 出たら職員に一言：「壁に出しました。〇〇に当ててみてください」
- 職員が「さっきのがいい」と言ったら `rollback_game`（同じ遊びの前の版）か `previous_game`（前の遊び）
