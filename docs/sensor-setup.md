# 測域センサの接続と記録（UST-20LX）

はじめてつなぐ日の手順。全部で30〜40分の見込み。
スマホで見ながら進めるときは、要点だけの [チェックリスト](sensor-checklist.md) を使う。

## 1. つなぐ（5分）

1. センサーに電源をつなぐ。青いランプが点滅し、10秒ほどで点きっぱなしになれば起動できている（点滅が続くときは異常）
   - 電源と入出力のケーブルは、先がばらの6本の線。使うのは**茶（＋）と青（−）の2本だけ**。直流 12V か 24V（10〜30V）、1A 以上の AC アダプタにつなぐ（起動の瞬間は 450mA ほど流れる）
   - 残りの4本（赤・灰・水色・橙）は使わない。先が互いに触れないよう、1本ずつテープで絶縁する
   - プラスとマイナスを逆にすると壊れる。テスターがあれば、つなぐ前にアダプタ側の向きと電圧を確かめる
   - 長く動かすと底が熱くなる。金属の板の上に置くか、金属に付ける
2. センサーと Mac を LAN ケーブルでつなぐ
   - Mac に LAN ポートがないので、USB-C の LAN アダプタを使う
   - アダプタがない場合は、自宅のルーターの LAN ポートにつなぎ、Mac は Wi-Fi のまま（下の「ルーター経由」）
3. Mac のネットワークを設定する：システム設定 → ネットワーク → 有線（USB LAN など）→ 詳細 → TCP/IP
   - IPv4 の構成：手入力
   - IP アドレス：`192.168.0.100`
   - サブネットマスク：`255.255.255.0`
   - ルーター：**空欄**（インターネットの通信が有線側に流れないように）

**Windows の場合**（3. の代わり）：設定 → ネットワークとインターネット → イーサネット（LAN アダプタ）→ IP 割り当ての「編集」
- 「手動」を選び、IPv4 をオンにする
- IP アドレス：`192.168.0.100`
- サブネットマスク：`255.255.255.0`（「サブネット プレフィックスの長さ」と出るときは `24`）
- ゲートウェイ：**空欄**
- 初めて `npm run dev:lidar` などを動かすと、「Windows セキュリティの重要な警告（Node.js）」が出る。「プライベート ネットワーク」に許可する（スマホから開くときにも必要）

**Wi-Fi も 192.168.0.x のとき**（家のルーターの多くがこの番号帯）：センサーと Wi-Fi の番号帯が重なる。
特に、Mac の Wi-Fi に `192.168.0.10` が割り当てられていると、ping は Mac 自身が返事をして通るのに、センサーにはつながらない（`sensor:check` が「ECONNREFUSED」や「つながりません」になる）。
Wi-Fi はつないだまま（スマホ画面と Claude に要る）、次をターミナルで実行する。`192.168.0.200` は家で空いている番号に、`192.168.0.1` は家のルーターの番号に、`en8` は LAN アダプタの名前に合わせる（`networksetup -listallhardwareports` で分かる）。

```bash
networksetup -setmanual "Wi-Fi" 192.168.0.200 255.255.255.0 192.168.0.1   # Wi-Fi の番号を、センサーと重ならないものに固定
networksetup -setdnsservers "Wi-Fi" 192.168.0.1
sudo route -n add -net 192.168.0.10/32 -interface en8                     # センサー宛てだけ LAN アダプタを通す
```

- 3行目の道は、再起動や LAN アダプタの抜き差しで消える。消えたら3行目だけ実行し直す
- `-host` ではなく `-net …/32` の形で足す（`-host` だと宛先が LAN アダプタ自身になり、届かない）
- スマホ画面を起動すると住所が2つ出る。スマホでは Wi-Fi の方（例：`192.168.0.200`）を開く
- 終わったら、Wi-Fi の設定を「DHCP サーバを使用」に戻す

**ルーター経由の場合**：Mac の Wi-Fi の IP が `192.168.0.x` なら、そのままでよい。それ以外なら、ターミナルで
`sudo ifconfig en0 alias 192.168.0.100 255.255.255.0` を実行して別名のアドレスを足す（再起動で消える）。
Windows では、管理者の PowerShell で `netsh interface ip add address "Wi-Fi" 192.168.0.100 255.255.255.0` を実行する（「Wi-Fi」は接続の名前。消すときは `add` を `delete` にする）。

## 2. 確かめる（5分）

```bash
ping -c 3 192.168.0.10     # Windows では ping -n 3 192.168.0.10
npm run sensor:check
```

「合格」と出ればよい。

**ping に返事がないとき**：センサーの IP アドレスが工場出荷時（192.168.0.10）から変わっている可能性がある。
1. 同じネットワークの候補を順に試す：`for i in $(seq 1 254); do ping -c1 -t1 192.168.0.$i >/dev/null && echo 192.168.0.$i; done`
   - Windows（PowerShell 7）：`1..254 | ForEach-Object -Parallel { if (Test-Connection "192.168.0.$_" -Count 1 -Quiet -TimeoutSeconds 1) { "192.168.0.$_" } }`
2. 見つかった IP で `npm run sensor:check -- --host <IP>` を試す
3. 別の番号帯（192.168.1.x など）に変えられている場合は、Mac の IP をその番号帯に変えて 1. を繰り返す

## 3. 置く

- 壁の投影範囲の**上辺の中央、少し上**に、走査の面が壁と平行になるように付ける（壁から数cm離す）
- センサーの正面が下（床の方向）を向くようにする
- 走査の面に、近くの家具やカーテンがかからないようにする

## 4. 記録する（15〜20分）

```bash
npm run record -- 2026-11-06-a
```

`recordings/2026-11-06-a.jsonl` に保存される。止めるときは Ctrl+C。
10秒ごとに「記録中：○回分のスキャン ／ この10秒の当たり ○回」と出る（スキャンが10秒で約400回増えれば正常）。
記録しながら、次の順に動く（それぞれ声に出して言っておくと、あとで分けやすい）。

| 順 | すること | 時間 |
|---|---|---|
| 1 | 誰も壁に近づかない（背景を覚える） | 10秒 |
| 2 | 投影範囲の四隅と中央を、順に手でタッチ（各2秒） | 20秒 |
| 3 | 手で壁をなぞる（左右・上下） | 20秒 |
| 4 | 柔らかいボールを壁に当てる（1人で、いろいろな場所に30回） | 1分 |
| 5 | 2〜3人で同時にボールを当てる | 1分 |
| 6 | 壁の前を人が横切る、壁の近くに立つ（誤って反応しないかを見る） | 30秒 |

記録の中に、コンピュータ名などの個人の情報は入らない（距離の値だけ）。

## 5. 記録を確かめる

```bash
npm run hub -- --source replay --file recordings/2026-11-06-a.jsonl
```

別のターミナルで `npm run web` を開き、`http://127.0.0.1:5173/?debug=1` で当たりの位置を見る。
（合わせ込みがまだなので、位置はずれている。数と反応の速さを見る）
